# TaskDec 动机与证据组织建议

日期：2026-09-15。本文是依据当前实现、实验和作者最新讨论形成的写作建议，尚未替代作者对标题和正文图表的最终决定。本轮只做资料核对与写作整理。

**推荐定位：面向多传感器 3D 检测，利用共享与特有表征指导目标相关的局部融合。**

一句话研究问题：在已经对齐的局部空间中，如何利用不同传感器之间的一致信息和差异信息，决定各模态特征怎样参与目标检测？

## 动机的逻辑顺序

1. **对齐建立了交互位置。** 不同模态映射到统一 patch 空间后，可以在对应位置进行融合；这一步本身不保证各路 token 对检测提供同样有用的信息。
2. **一致与差异都可能有价值。** 跨模态一致信息有助于建立共同表征；某一路独有的信息也可能是互补线索。差异同样可能来自噪声和背景，因此不宜把相似性直接视为可靠性的真值。
3. **让表示结构服务于融合决策。** 在目标相关区域学习 common/unique 状态，再用这些状态产生局部门控、传感器缩放和检测上下文，形成可以训练和检查的控制机制。

这里第 2 点是方法设计的出发点。当前结果尚未证明原始 attention 必然压制互补信息，也未单独证明 unique 中的具体信息类型；不能把研究假设写成已完成的因果诊断。

### 与已有方法的准确衔接

ASF 已经提出统一 canonical projection 和按 patch 的跨传感器 attention，并研究传感器退化和失效。因而“已有融合都是固定权重”“首次在局部自适应融合”不适合作为 TaskDec 的创新表述。[ASF 官方论文页面](https://proceedings.neurips.cc/paper_files/paper/2025/hash/80bd5c815cdb033ac23eb27605adaaba-Abstract-Conference.html)

共享/特有表征分解也已有直接相关工作，例如 DecAlign 的 common/unique 表征与跨模态对齐；不能仅凭使用两个分支宣称首次提出解耦。[DecAlign 官方论文页面](https://proceedings.iclr.cc/paper_files/paper/2026/hash/f7f5f501282771c96bb3fedcc96bedfe-Abstract-Conference.html)

TaskDec 应集中解释自己的具体设计：**在空间 patch 上学习共享/特有状态，并让它们与目标监督共同参与融合输入、query 和输出的调制。** 这一定位来自本项目的计算链，不构成对全部相关文献完成排他性新颖性检索的结论。

## 引言中文草稿

多传感器 3D 检测需要有效利用不同观测中的共享信息与互补线索。统一空间表示使相机、LiDAR 和雷达特征能够在对应的局部区域进行交互，但处于同一空间位置的特征仍可能具有不同的信息构成：其中既包含跨模态一致的目标线索，也包含模态特有的差异和背景响应。因此，在建立空间对应关系之后，融合还需要考虑这些信息与检测任务的关系。

这一问题带来一个具体的设计需求：在利用跨模态一致性的同时，保留可能有助于检测的模态特有信息，并使局部融合受到目标相关性的引导。现有跨传感器注意力能够根据输入调整交互。我们进一步研究，显式组织共享与特有表征，并将其作为融合控制的条件，能否改善多传感器 3D 检测。

为此，我们提出 TaskDec，一种任务感知的解耦融合方法。TaskDec 在统一 canonical patch 空间中学习跨模态共享状态与模态特有状态，并在目标相关区域施加表征约束。基于这些状态，模型预测前景门控与传感器缩放系数，同时生成检测任务上下文来调制融合 query 和输出。该设计将表征学习与局部融合控制联系起来，使共享与特有状态直接参与最终检测表示的构建。

这三段是无引用键的内容草稿。正式英文引言需在空间对齐、注意力和解耦相关表述处补对应文献；实验段根据最终入选结果另写。恶劣天气、低照度等可在第一段中作为信息差异的例子，不必成为全文的唯一起因。

工作标题仍可采用：**TaskDec: Task-Aware Decoupled Control for Multi-Sensor 3D Detection**。若最终主文突出完整 TaskDec，v2 的 Strong 需明确标为不含 task context 的 Dec 家族变体。

## 方法术语与实现对应

| 术语 | 当前实现 | 写作边界 |
|---|---|---|
| Common / unique | 分别由模态 MLP 生成；前景 patch 上做 common 一致、unique 差异及 common–unique 去相关约束 | 没有重构约束要求原特征严格等于二者之和；不声称统计独立或已分离真实语义因素 |
| Unique | 模态特有状态，同时用于控制和特征残差 | 不能直接定义成噪声；是否保留有用互补线索需依靠检测证据验证 |
| Foreground gate | 预测前景相关的控制强度 | 空间 gate 不是模态选择图，也不是已经校准的传感器可靠性概率 |
| Sensor reliability | 学习得到的模态评分和受限 token scale | 当前统计偏向 LiDAR，不支持随天气频繁切换主导传感器的描述 |
| Task context | 由局部状态生成上下文，注入 query 和融合输出 | v1 单类别实际是 objectness context；不应描述为分类/回归任务解耦或复杂多类别语义推理 |

实现依据：[融合器](../models/fuser/patch_dec_a2_fusion.py)、[主配置](../configs/ASF_task_dec_controlled_robust_v1_0.yml)、[已核对的计算链](taskdec_project_and_paper_review_260909.md)。检测 GT 用于训练监督和可视化参照，不是融合器推理时的输入。

## 动机图和论证重点

独立动机图可以由三个相连部分组成：同一场景的对应局部观测；该局部特征中的共享与特有信息示意；这些状态在目标相关控制下进入融合。用同一帧的多个区域解释局部性，会比只并列晴天和雨雪更贴合 TaskDec 的设计。

示意部分必须标注为概念图。现有真实相机与 BEV gate 素材可支撑空间对应的展示，但尚不能代替 ASF–TaskDec 检测预测对比，也不能把假定的“共同目标/互补线索/噪声”画成已经获得逐项真值的分解结果。

最值得进一步回答的机制问题是：**同等容量的控制器直接使用原始 token，是否就能达到相同效果？** 现有“去解耦监督”保留了分支结构，提供了相关证据，但尚不是这个直接对照。如果后续安排一项针对动机的补充实验，可优先考虑参数量与选择流程可比的 raw-token controller 对照。该建议不在本轮启动。
