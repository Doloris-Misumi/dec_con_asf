# V2X-Radar-V：TaskDec 后续趋势与行人定位改进判断

日期：2026-09-16 23:26 起。仅读取已有验证、审阅代码并抽查训练标签；没有占用 GPU，也未改变正在运行的训练。

**判断：现有结果更支持小目标精细定位不足；尚不能确定具体是中心、尺寸、朝向或分数排序，也不能直接归因于 task 分支。**

**能否接近 Concat？** TaskDec 最新完整验证第50轮为67.54893，目前训练已进入第53轮；Concat第75轮为74.30547，尚缺6.75653点。TaskDec的40→45、45→50均值分别增加3.11686和1.51271；但同轮相对Concat的差距由40轮5.15407缩到45轮2.49441后，又在50轮扩大到3.48599。继续进步有依据，保证在80轮追上74以上没有依据。
供理解尺度的条件算例：Concat从50→75轮自身增加3.27054；若TaskDec接下来25轮恰好增加相同数值，会达到70.81947，这不是预测。保持TaskDec车辆/骑行者第50轮数值，只让行人追到Concat第75轮的62.02671，均值为71.33274，仍需其他两类继续提高。

**同为第50轮的行人指标，1,487帧完整验证。**

| Moderate 指标 | TaskDec | Concat | TaskDec − Concat |
|---|---:|---:|---:|
| 3D AP@0.25 | 77.02 | 78.02 | -1.00 |
| 3D AP@0.5 | 50.68 | 58.70 | -8.03 |
| BEV AP@0.25 | 77.89 | 78.49 | -0.60 |
| BEV AP@0.5 | 57.33 | 64.22 | -6.90 |

宽松IoU下已相当接近，严格IoU下3D与BEV差距明显扩大，故水平位置、占地尺寸、朝向等精细几何应优先排查。BEV差距说明问题不只在高度；AP同时受召回、分数排序和误检影响，不能由该表证明分类已完全正确。

**架构中与该现象有关的事实。**

- BEV输入单元0.4m，4×4 patch覆盖1.6m×1.6m；每模态把4×4×64个值映射为128维patch token，再由16个query恢复细网格。Flatten保持空间顺序，不能称为完全抹除位置，但压缩使细节恢复更依赖学习。
- 当前任务上下文是patch级类别概率，经foreground gate调制后，作为相同增量广播给该patch的各query及输出token。不同query仍有各自可学习向量，输出并非必然相同；但这个辅助分支本身没有区分patch内部16个位置。
- 类别标签依据patch中心是否落在扩展0.7m的GT框内确定；同一个patch被不同类别覆盖时，当前实现由最后一个GT覆盖标签。它不等于中心热图或位置偏移监督。
- Concat与TaskDec使用相同BEV分辨率、neck、head；不能只把共用检测网格粗归咎于TaskDec。主要可区分因素是进入head之前的patch压缩、解耦与控制。

**改进顺序建议（尚未实施）。**

1. 先用固定验证样本、同轮checkpoint对预测框作几何误差拆分：采用相同匹配规则比较中心xy偏差、长宽偏差、yaw和高度，按距离/点数/人群密度分组；在相同置信度或相同FP水平比较召回。只记录汇总量及少量失败案例，不保存全量特征。使用验证集进行设计选择，测试集保留最终报告。
2. 优先独立验证小patch：4×4→2×2，对应1.6m→0.8m；当前实现应同时将query数16→4，以保持输出128通道和原neck接口。每模态压缩从1024→128变为256→128。局部patch数增为4倍，不能视为零成本变化；需单独测显存/吞吐。给patch和TaskDec设置对应对照，才能区分基础patch粒度与解耦控制的作用。
3. 若仍存在定位差距，再把task context扩展为类别与局部几何共同条件：在细网格预测按类别的中心响应和相对位置，让patch内各query获得不同位置条件，保留common/unique与控制作为主融合结构。中心/偏移监督仅训练时使用GT；推理使用预测，不能靠GT选择细粒度路径。这是独立架构改动，需要重新训练验证，当前结果不证明它必然有效。
4. 对重叠目标的辅助标签可改为多标签类别存在监督，或明确、与遍历顺序无关的空间匹配规则。不同问题需要不同处理：类别存在可multi-hot；中心回归仍需空间或实例匹配。不能把多个同类行人的中心简单平均成一个虚假目标。
5. 不优先提高行人分类权重；宽松IoU差距小，而当前辅助分类损失已有逆频率权重。早期控制饱和可作为第二条独立假设，使用mild控制或渐进启用验证，不能把epoch22的饱和直接当成epoch50仍如此。
6. 当前80轮固定实验继续完成。patch基线成熟后的定位表现有辨别价值：若它也明显弱于Concat，优先检查共同patch路径；若它接近Concat而TaskDec差，则重点隔离解耦/控制/任务监督。不得由此直接认定唯一原因，也不要中途改当前配方。

**论文表述与文献边界。** Concat目前是强本地三模态基线；与官方表的数据划分、ROI、输入模态不同，不能直接把74.31表述成已战胜全部文献。这里的目标是解释并缩小同协议TaskDec–Concat差距。
中心几何监督可参考CenterPoint以中心检测与属性回归组织3D检测的思路；这提供设计依据，不意味着需要替换现有检测头，也不证明所提TaskDec修改已经有效。[CenterPoint原论文](https://arxiv.org/abs/2006.11275)。官方单车实验与协议见[V2X-Radar论文](https://arxiv.org/html/2411.10962v3)。
