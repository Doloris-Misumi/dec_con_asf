**K-Radar 上的 VLM、世界模型与 WAM：可行性与候选课题**

2026-09-19。WAM 在本文中按 World Action Model 理解。以下是基于公开文献与数据说明的研究建议，尚未进行本地时序数据完整性审计，也未启动新实验。

**可行性判断**

K-Radar 可以用于三维空间语言理解，也具备探索未来场景预测与自车轨迹联合建模的部分条件。优先级建议为：目标级 VLM／空间 grounding → 目标或 BEV 状态的世界模型 → 经动作与评测链路补齐后的 WAM。

已有三篇相关工作分别偏雷达—语言对齐、场景描述、时序空间与运动理解，并不等于都已经完成驾驶动作生成：

- [SKD-4R，IV 2026](https://ave.kaist.ac.kr/2026/02/12/structural-knowledge-distillation-for-aligning-4d-radar-with-vision-language-models/)：通过 CLIP 的关系结构蒸馏，对齐雷达与视觉语言空间，并构建 K-Radar-language。语言标注公开下载状态尚未确认。
- [Weather-Robust Scene Semantics with Vision-Aligned 4D Radar，2026 Workshop](https://arxiv.org/abs/2605.07367)：研究 K-Radar 恶劣天气下，由雷达特征支持的结构化场景描述。
- [Radar4D-VLM，2026 预印本](https://arxiv.org/abs/2608.04130)：使用时序雷达与目标、场景和运动 token 进行语言推理；其直接预测头未显示来自语言对齐监督的稳定增益。因此应分别验证传感器表征作用与语言作用。

**三种任务的区别**

| 任务 | 输入与输出例子 | 必要证据 |
|---|---|---|
| 目标级 VLM | 当前／历史观测＋问题 → 文字答案＋对应三维目标 | 答案正确且能定位到传感器证据 |
| 世界模型 | 历史观测 → 未来目标、BEV 或场景潜在状态 | 多时刻预测优于静态延续、运动外推等基线 |
| 世界—动作模型 | 历史观测／目标 → 未来场景＋自车行动；或以候选行动条件预测后果并参与选择 | 动作、未来状态相互一致，且有规划或执行收益 |

WAM 的架构命名尚在发展，不能简单按是否带一个未来预测 loss 分类。[DreamZero](https://arxiv.org/abs/2602.15922) 展示了联合生成视频与机器人动作的路线；自动驾驶中，[ProphetDWM](https://arxiv.org/abs/2505.18650) 研究未来视频与动作联合预测，[DA-WAM](https://arxiv.org/abs/2608.19085) 将行动条件下的未来潜在状态直接用于候选轨迹评分。

**候选一：有三维依据的多传感器空间语言理解**

研究问题：当相机或 LiDAR 观测质量下降，模型能否仍然根据多传感器证据回答问题，并指出对应目标？

示例：“左前方最近的车辆在哪里？”输出对象标识、3D box 和自然语言回答；“前方某区域内有几辆车？”输出计数及支持该计数的框。问题必须限制在数据实际能够验证的范围。

可复用 ObjDec 的目标相关融合、WCBR 对观测质量变化的建模经验；再引入语言与对象表示的对应关系。真正需要证明的贡献是观测退化下的 grounding 可靠性、几何精度和证据一致性，不能停留在把检测结果写成一句话。

最小对照：直接结构化感知头、普通语言投影、关系蒸馏、拟议方法。保留无语言／打乱语言对照；避免同模板问答造成虚假的理解能力。测试集至少包含独立核验的答案与目标对应关系，按序列划分并检查语言改写泛化。

可用指标：检索 Recall、目标定位准确率或 IoU、区域计数／关系准确率、无法由传感器支持的对象陈述率，以及正常／恶劣天气分组。检测 AP 单独报告。

**候选二：多传感器目标状态的未来预测**

这是更接近世界模型、又能直接利用三维感知资产的方案。输入当前及过去多帧 C/L/R，形成目标状态或 BEV 潜在表示，预测后续时刻的目标位置、空间占据或稳定的未来表征。语言分支可以在后续加入，用于解释可验证的变化。

建议的核心问题：**观测退化时，如何利用不同传感器和历史信息维持可预测的物理状态？** 例如当前图像模糊时，能否结合历史轨迹与雷达观测继续预测目标，而不是逐帧丢失它。

天气既会影响观测，也可能影响驾驶行为和路面动力学；不能预先把全部天气影响归入噪声。共享物理状态、模态观测差异与真实运动变化，需要通过具体监督和对照区分。这只是候选研究假设，不构成已验证的创新声明。

先预测对象／紧凑 BEV，比一开始生成完整高清驾驶视频更利于定位问题与控制成本。若做占据，K-Radar 的检测框并不等于密集语义占据 GT，需要自行构建并验证；未被观测区域不能都当作空闲空间。[OccWorld](https://arxiv.org/abs/2311.16038) 可作为占据与自车运动联合预测的参考，但其现有基准与监督条件不能直接移植。

最低限度对照：静态延续、仅自车位姿变换、目标匀速外推、普通时序融合、拟议方法。完成自车运动补偿后再判断动态预测增益，否则只是预测视角变化也可能取得很好的分数。

根据真实时间戳与序列覆盖率预先确定预测跨度，再报告各跨度的目标位置误差、未来检测表现或占据指标。跟踪 ID 是否跨帧可靠需要先核查；没有可靠 ID 时，应建立关联与质量控制，不直接假定存在完整轨迹真值。

**候选三：在世界模型上增加自车轨迹，形成 WAM 研究**

K-Radar 官方提供 KITTI 格式位姿、相对位姿、GPS 与独立 IMU 资源。位姿由 LeGO-LOAM 等处理得到，并非所有帧都能简单按序号对应；应使用 info_label 对齐。部分恶劣天气与隧道序列存在里程计质量问题。[官方 odometry 文档](https://github.com/kaist-avelab/K-Radar/blob/main/docs/odometry.md)

因此可以从可信位姿构造未来自车轨迹，作为运动预测或模仿目标。轨迹不是方向盘／油门的直接控制记录；若以轨迹作为行动表示，需要明确执行接口和限制。

建议分两级推进：

1. 离线联合预测：历史传感器 → 未来场景状态＋自车轨迹。对齐未来状态坐标系，评估预测误差、运动一致性和类别／天气子集。
2. 行动条件预测与规划：输入候选轨迹，预测其对应后果，并将后果用于候选选择。需要额外规划基准或可交互仿真验证，不能只凭记录轨迹上的误差宣称闭环驾驶能力。

K-Radar 每段记录只展示实际执行的一种未来。将候选动作换掉后，生成的未来是否正确，不能仅靠该记录的 GT 判断。还需要区分简单坐标变换与其他交通参与者对自车行为的真实响应。完整 WAM 的难点主要在监督与验证链路，而不只是显存。

如要进一步覆盖规划，适合在具有相应评测机制的数据／仿真上补实验，把 K-Radar 保留为恶劣天气多传感器理解与预测的重点基准。

**与现有机器人项目的连接**

在 RoboCasa365 上，用户已经具有 π0.5 的动作学习链路；探索当前场景几何与未来对象／夹爪关系的联合建模，会比从 K-Radar 重建动作接口更直接。K-Radar 则更适合利用既有 C/L/R 模型研究观测退化下的状态估计与预测。

目标级世界—动作建模本身也已有相近工作：[OA-WAM，2026 预印本](https://arxiv.org/abs/2605.06481) 以对象 slot 表示未来状态并生成动作。因此不能把“从图像换成对象 token”单独当作尚无人研究的贡献。

**推荐范围**

若另开 K-Radar 项目，先在“可靠空间 grounding”和“退化观测下的目标状态预测”中选一个主任务。后者可以向 WAM 延伸，也与 ObjDec、WCBR 形成连续的研究问题。当前阶段无需同时叠加语言生成、视频生成、预测与规划四套目标。

下一步最有价值的工作是只读核查数据：连续时间窗口覆盖、里程计质量、跨帧对象关联、原始速度字段、可用语言标注及序列隔离划分。通过这一步再定具体预测时间尺度、模型规模和实验预算。
